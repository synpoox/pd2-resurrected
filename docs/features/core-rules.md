# core-rules hook list

One row per engine rule (see `GLOSSARY.md`). Hand-edited. Built by research ticket [#19](https://github.com/synpoox/pd2-resurrected/issues/19); method, evidence and open questions are in
[docs/features/core-rules-inventory.md](core-rules-inventory.md).

Columns:

- **PD2 source**: table column and value (`srvdo` = skills `srvdofunc`, `cltdo` = `cltdofunc`, `srvst`/`cltst` = start functions,
  `prg` = `srvprgfunc1-3`/`cltprgfunc1-3` (`srvprg`/`cltprg` for one side), `shit`/`chit` = missiles `pSrvHitFunc`/`pCltHitFunc`, `sdo`/`cdo` = missiles
  `pSrvDoFunc`/`pCltDoFunc`, `dmg` = `pSrvDmgFunc`), or the DLL source for server rules.
- **Bucket**: (a) data only, (b) D2RLoader service, (c) native hook, (d) UI rebuild, (e) cut.
- **D2R slot**: PD2's number where that slot is free in D2R. `->` marks a re-map (collision or past the table end), logged here.
  Slots 191+ need the srvdofunc overflow table (plumbing, see the research file, Q1).
- **RVAs**: names only; the values live in the per-build header. `?` = not located yet.
- **Tier**: Exact or Function-equivalent (glossary).
- **Size**: sessions. S under 1, M 1-2, L 3+. Every size here is an estimate from the spike, not measured.
- **Status**: `spiked` (proven in a spike), `open` (to build), `verify` (a value inside D2R's range, or a rule whose effect is not
  yet confirmed: treat as different from D2R until checked), `data` (no plugin code expected; listed so the check is not lost),
  `unreachable` (no row reaches it in play; not added to the deviation list), `cut`.
- **Work item**: the build slice that carries the row (see Work items below); empty = after the alpha 0.1.0 cut (in the alpha), in the order
  below. map system rows name their `MS` work item from [map-system.md](map-system.md), whose map-only code lives in `core-events`; uber boss rows name their `UB` work item from [uber-bosses.md](uber-bosses.md); item rule rows name their `IR` work item from [item-rules.md](item-rules.md); `later release` rows wait for multiplayer.
- **Test**: the log assertion the `tests/game/` check makes. Expected values come from PD2's data unless noted.

## Work items

Ordered by "Order and slice core-rules into work items" ([#25](https://github.com/synpoox/pd2-resurrected/issues/25)); placed into milestones, next to the P items, by [roadmap.md](../roadmap.md). A work item is about one agent session. A `verify` check is
the first step of the item that builds its row; when D2R already matches, the item shrinks to data. Each build PR merges
when its game check, the table-diff gate and a code-review agent pass; the owner reviews P1, W1, [W2](https://github.com/synpoox/pd2-resurrected/issues/45) and the alpha 0.1.0 release.
Target: D2RLoader 1.3.1, whose own engine image (`0x6ab3782c`, build 93847's code) runs with D2R 3.4 (95032) or 3.3 (93847) data; addresses are the image's, so one build serves both ([#1509](https://github.com/synpoox/pd2-resurrected/issues/1509)).

## Hot-path log lines (#1609)

A log line per hit, arrow, missile, kill or drop stalls the game thread (D2RLoader flushes each line to disk, about 5 ms), so those lines write **nothing in normal play**. `pd2::HotSample` (`plugin/common/hot_log.h`) lets a line through only when the game process has the environment variable `PD2R_HOT_LOGS=1` (read once at load; not `debug_mode`, which every cheat test turns on); then it logs the first 20 calls and one in 500 after. A game check that reads a hot-path line (`multiple shot:`, the missile-hit lines, `uber scaling:` minions and the like) sets it before starting the game: `$env:PD2R_HOT_LOGS = '1'` in the shell that runs `game_ctl.py ... start`. Boss phase lines, load lines and error warnings are not hot and log always. `tools/tests/test_hot_path_logging.py` fails a sampler that skips the flag.
