# merge/

The committed rules `tools/pd2_merge.py` applies to the extracted PD2 data (`pd2-data/`) to write `generated/data/`
(ADR 0002): id remaps, event names, function-number rewrites, D2R-only rows kept or off. Names and numbers only, never PD2
row data. Every id the port adds is assigned here once and is append-only (ADR 0003).

Each file is read by the rule kind its name maps to in `pd2_merge.RULES`; a file with no rule kind fails the merge.
Column-level rules (references, formulas, derived columns, function-number rewrites) are constants in
`tools/pd2_ids.py` (REFS, FORMULAS, DERIVED, FUNCS).

| File | Rule kind |
|---|---|
| `strings.json` | `tools/pd2_strings.py`: PD2's `patchstring.tbl` into complete D2R string files (decision [#29](https://github.com/synpoox/pd2-resurrected/issues/29)). `python tools/pd2_strings.py --assign` appends newly referenced keys with IDs from 50,000; never edit or reuse an ID. The 20 changed guild, ladder and arena labels are left out (cut features). `ModStr5q`, `StrSkill110` and `StrSkill76` keep D2R's text: PD2's drops the `%d` D2R fills in. `Runeword171PD2` carries PD2's Runeword171 (Dominion); `runes.txt` must name it |
| `ids-<table>.tsv` | `tools/pd2_ids.py`: append-only id lists for the tables a save or D2R's code reads by row number: the P2 skill, state, stat and missile tables, the item types, unique and set items, runewords and affixes, and the level tables (levels, lvlprest, lvlwarp, objects, objgroup; objtype follows the objects list). An id of `-` leaves a PD2 row out: the areas out of the Alpha (PvP, PD2's Uber Ancients, the Butcher's Lair, the guild halls) and PD2's `<reserved>` objects rows. A `-` becomes the next free id when its area is ported; no other line ever changes. A line whose first column is `+<id> col=value ...` is a row the port adds ([WL1](https://github.com/synpoox/pd2-resurrected/issues/233)'s Warlock affixes): a copy of the earlier row `<id>` with those columns set, at an id after D2R's rows |
| `ids-monpreset.tsv` | `tools/pd2_levels.py`: monpreset's append-only list, `<act>/<place>`, the index within the act a DS1 names a monster by. PD2's rows past D2R's append to their act |
| `level-files.tsv` | `tools/pd2_levels.py`, after the id rules: writes lvltypes (PD2's new types, naming only the files the PD2-only presets select; in D2R's types the DT1 the PD2-only presets select, moved to a free slot where D2R's file sits, with the presets' `Dt1Mask`), objpreset (a row per object a PD2 DS1 places in an act that has none for it), the PD2-only presets' DS1 with their object and monster ids rewritten (a monster no monpreset row of its act names gets one appended), and the DT1 they load that D2R lacks (the 3 PD2 ships over vanilla paths go to `pd2assets/v/`). The file lists the DS1 objects the rewrite leaves out, with why; any other object it can't resolve fails the merge, as does a PD2 lvlwarp `Id` that clashes with D2R's. With it, `tools/pd2_automap.py` adds PD2's automap cels past D2R's (1499 and up) to D2R's HD tiles, upscaled from PD2's `MaxiMap.dc6`, and ships PD2's classic `MaxiMap` and `MaxiMapS`; an automap cel past them fails the merge |
| `item-tables.txt` | `tools/pd2_items.py`: the item tables merged by key or row with no id list, and the item types and codes that never drop. PD2's own item pictures (an invfile no D2R item uses) get HD sprites upscaled from their DC6 (`art/`), in the folder of every item table drawing them, and their `items.json`, `uniques.json` and `sets.json` entries |
| `tables.json` | `tools/pd2_tables.py`: the tables with no id list that the merge takes over from D2R, each with how its rows pair (name, position or key columns), whether PD2-only rows append or are left out, whether a repeated name takes PD2's whole group, the columns that keep D2R's values, the only rows it merges (`only_rows`: inventory's cube rows, #299), and the PD2 ids moved past D2R's (`move`: hireling 30-38 to 39-47), and single cells set after the merge (`cells`: the hireling monsters' monstats NameStr, #272). A table not named here ships as D2R's; `docs/deviations.md` lists why |
| `missiles-hd.tsv` | `tools/pd2_missiles_hd.py`, after `ids-missiles.tsv`: writes `data/hd/missiles/missiles.json`, D2R's map plus one entry per missile PD2 adds, taking the model of the D2R missile with the same `CelFile`. Each line names the D2R missile (`like`) for a new missile with PD2-only art; a new missile with neither fails the merge. Temporary: the models of every `rathma*` and `lucion*` missile (hand-picked or by CelFile) are stand-ins until PD2's art is merged in. A name with capitals gets its entry under both spellings, lower case and its own (JSON keys are case-sensitive; whether D2R lower-cases a missile name is unproven) |
| `panel-grids.json` | `tools/pd2_panels.py`: D2R's panel art redrawn one cell column wider where PD2's grid is wider (the cube, #299): HD, lowend, controller and classic DC6, each with where D2R's art draws its grid. `patches/050-cube-grid.json` moves the layouts' grids to match. The classic DC6 needs `python -m modkit fetch legacy-ui` |
| `monsters-hd.tsv` | `tools/pd2_monsters_hd.py`: writes `data/hd/character/monsters.json`, D2R's map plus one entry per monster PD2 adds, taking the model of its `BaseId` when that D2R monster has the same `Code`, else the model most D2R rows with its `Code` use. Each line names the D2R monster (`like`) for a new monster with PD2-only art, a tie between two models, or a wrong pick; a new monster with no model, or a line that picks what the monster gets anyway, fails the merge. Keys are the exact `Id` (D2R's lookup is case-sensitive) |
| `skill-icons.txt` | `tools/pd2_skill_icons.py`: the classes whose skill icon sheets come from PD2 (`pd2_extract` takes them from `pd2assets.mpq`). Each, and the shared sheet of class-less skills, gets PD2's classic DC6 as it is and an HD strip (and lowend) with a frame per DC6 frame: D2R's HD frame where PD2's classic frame is D2R's or PD2 has none, else PD2's upscaled (`art/`). A listed class with no PD2 sheet, or an extracted sheet not listed, fails the merge |
| `art/` | not a rule: `tools/pd2_art.py`'s cache, `<name>-<hash of the classic frame>.png`: PD2's item pictures upscaled 4x by Real-ESRGAN (`realesrgan-x4plus`), and its skill icons finished in D2R's style at the HD size. Committed, so the merge makes art only for a frame with none (with Real-ESRGAN, numpy and Pillow). Delete a sheet's files to remake them after changing the style |
| `tree-backgrounds.json` | `tools/pd2_skilltrees.py`, after `tables.json`: redraws each class's skill tree sprites (HD, lowend, controller) from D2R's own: tab strip kept, a box at each merged skilldesc SkillPage / SkillRow / SkillColumn and an arrow from each `reqskill` on the same page, in D2R's box and arrow art. The file holds where D2R's art draws its grid in each sprite kind, measured on build 93847. The Warlock keeps D2R's tree |
| `vfx-overlays.tsv` | `tools/pd2_overlays_hd.py`, after `tables.json` (which keeps D2R's overlay `Character`, the HD folder, on shared rows): each overlay PD2 adds takes the folder of a D2R overlay (`like`) and a copy of its json, `data/hd/overlays/<folder>/<overlay>.json`. A new overlay with no line, or a line for one that is not new, fails the merge |
| `standins.tsv` | `tools/pd2_standins.py`, after the id rules: each line points a merged skill, missile, item or property row's function columns at a D2R row (`=` its own, a name, `-` blank) until the core-rules rule is built. The merge fails if a PD2 row keeps a function number D2R lacks (`PD2_ONLY`). Every line's rule is on `docs/deviations.md` (a row, or an exact data row). When a rule is built, delete its lines, its row and its numbers in `PD2_ONLY` |
